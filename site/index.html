Getting started

Drive PicoForge from any AI agent

PicoForge is a local computational engineering studio. Connect Claude Code, Codex, Gemini CLI, Cursor or VS Code to it over MCP, and your agent can design parts while you watch them build in the PicoForge viewport and edit them yourself.

Fill in your repository URL below and every command and prompt on this page updates. The token is only needed for the HTTP connection; stdio does not need it.

Stays in this browser only.

Quickstart prompt

Paste this into your agent. It checks prerequisites, installs PicoForge, connects itself, and confirms the tools are available. It asks before installing system software.

Install and connect

One prompt from nothing to a connected agent.

Install and connect PicoForge.
1. Check that Deno ≥ 2.2, .NET SDK ≥ 9 and Git are installed. Ask me before installing anything missing.
2. Clone {{REPO}} into a folder named picoforge and run `deno task setup` inside it.
3. Start it with `deno task start` and run `deno run -A server/main.ts --selftest`; it must exit 0.
4. Register the MCP server for this client using stdio (command `picoforged`, args `--mcp`). Use this client's own MCP configuration method.
5. Reload MCP servers (or tell me to restart the session) and confirm the picoforge tools are listed.
6. Load the `forge_engineer` prompt from picoforge and summarise the working loop in five lines.

Install PicoForge

Shell
git clone {{REPO}} picoforge
cd picoforge
deno task setup        # restores PicoGK, builds the engine, generates the API card
deno task start        # 127.0.0.1:7317, opens the app window
deno run -A server/main.ts --selftest

The first launch asks for your model API key and runs a self-test that builds a 10 mm cube. When the cube appears, the engine works.

Connect your agent

stdio is recommended. The client starts picoforged --mcp, which attaches to the running app, so there is no token to copy. Use HTTP only when the agent runs somewhere that cannot start a local process.

Shell
claude mcp add picoforge -- picoforged --mcp

Add --scope project to share the server with everyone who opens the project (writes .mcp.json).

~/.codex/config.toml
[mcp_servers.picoforge]
command = "picoforged"
args = ["--mcp"]
~/.gemini/settings.json
{
  "mcpServers": {
    "picoforge": { "command": "picoforged", "args": ["--mcp"] }
  }
}
.cursor/mcp.json
{
  "mcpServers": {
    "picoforge": { "command": "picoforged", "args": ["--mcp"] }
  }
}
.vscode/mcp.json
{
  "servers": {
    "picoforge": { "type": "stdio", "command": "picoforged", "args": ["--mcp"] }
  }
}
Claude Code over HTTP
claude mcp add --transport http picoforge http://127.0.0.1:7317/mcp \
  --header "X-PicoForge-Token: {{TOKEN}}"

The app must be running. The token is shown in PicoForge → Settings → MCP connections, where you can also rotate it and revoke clients.

Client configuration formats change. If a snippet is rejected, check that client's MCP documentation; the values (command picoforged, argument --mcp) stay the same.

Verify the connection

  1. Ask your agent to list the picoforge tools. You should see open_project, submit_design_brief, define_part, run_build and others.
  2. In PicoForge, the top bar shows AGENTS 1. Settings → MCP connections lists the client by name.
  3. Ask the agent to build a 20 mm cube in a project called "Hello". It appears in your viewport with a small mcp · <client> chip on its run card.

The working loop

Agents follow this order. The server enforces the important parts, so skipping a step returns an error with the next step to take.

  1. Load the forge_engineer prompt and read picoforge://api/picogk-card.
  2. open_project; read picoforge://session/selection and /pins if the human points at something.
  3. search_docs for a matching recipe and the relevant formulas.
  4. submit_design_brief with parameters as expressions, targets and physics checks.
  5. define_part once per part; every dimension from ctx.P("name").
  6. assemble, then run_build with stage final; poll get_run if it returns a handle.
  7. On failure, follow repairHint and re-send only the failing part.
  8. inspect_geometry, then report numbers with units and their analysis tier.

Prompt library

Copy a prompt, replace the angle-bracket parts, and paste it into your agent.

Design something new

Full loop from description to validated part.

Using the picoforge MCP server: load `forge_engineer`, open project "<project name>", then design <what it is, sizes, loads, material, how it will be made>. Submit a brief first, define parts one at a time, assemble, run the final build, and inspect the result. Report volume, mass, minimum wall thickness, and any failed or unverified checks. Respect all pins.

Change an existing design

Edit parameters or move parts without regenerating everything.

In picoforge project "<project name>", variant "<variant>": call `get_scene`, then change <what> using `set_param` or `transform_part` with the current `baseRev`. Rebuild only what is affected and give me before and after numbers.

Design around what I selected

Uses the human's selection and pins in the viewport.

Read `picoforge://session/selection` and `picoforge://session/pins` for project "<project name>". Design <a bracket, clamp, duct…> that mounts to the selected feature, keeps every pinned feature unchanged, and stays inside <envelope>. Show me the brief before building.

Optimise (Raman mode)

Long study with a ledger of rounds.

In picoforge project "<project name>", start a RAMAN study on variant "<variant>". Goal: minimise mass. Constraints: <safety factor, max deflection, envelope, min wall>. Poll `get_study` every minute. When it stops, show the best three rounds from the ledger and recommend one, with each number's analysis tier.

Review a design

Structured critique before making the part.

Load the `forge_review` prompt for variant "<variant>" in picoforge project "<project name>". Review loads, walls, overhangs, fits and mass, and list the three most important fixes with the parameter changes you would make.

Export for manufacturing

Files for printing or cutting.

Export variant "<variant>" of picoforge project "<project name>" as <stl | 3mf | glb>, one file per part, and tell me each part's volume, mass and bounding box.

Rules for agents

  • Never build before the brief is accepted (BRIEF_REQUIRED).
  • Never edit the user region of the design file; it holds the human's direct edits.
  • Never remove or work around a human pin. If a pin blocks the goal, explain and offer options.
  • Send baseRev from your latest get_scene; on STALE_REV, re-read and re-apply.
  • One run per variant. Use fork_variant to try alternatives in parallel.
  • Label estimates. Results from analysis tier A2 are indicative, not certified.
  • On NEEDS_DECISION, stop and ask the human using the options provided.

Limits

Agents cannot change settings or keys, clear the cache, delete projects, see file paths, remove a human's pin, or move the human's camera. The human's Stop button cancels agent runs too.

Troubleshooting

SymptomFix
Tools do not appear in the agentReload MCP servers or restart the agent session; check that picoforged is on PATH
picoforged: command not foundUse the full path to the binary in the config, or add the folder that contains it to PATH
HTTP connection returns 401Token missing or rotated; copy the current one from Settings → MCP connections
Self-test fails at the engine stepInstall the .NET 9 SDK and run deno task setup again
Builds fail with OOM on a small laptopExpected on very large parts at fine resolution; accept the suggested voxel size or split the part
The agent cannot see what I selectedSelect in the viewport first, then ask; the agent reads picoforge://session/selection

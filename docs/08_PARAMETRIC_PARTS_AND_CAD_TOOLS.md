# 08 · Parametric parts and CAD tools

Every design is a graph of named parts and operations driven by parameters. The user can grab any part, move it with axis arrows, combine parts with booleans, change any parameter or equation, and add NURBS surfaces. Every one of those edits is reflected in C# code that can be copied and run elsewhere.

## 1. The scene document

```
Variant
 ├─ params        name → { expr, value, unit, governing, source }
 └─ nodes (tree)
     ├─ part            generator = "Parts.Arms",  trs, material, visible
     ├─ part            generator = "Parts.Plate"
     ├─ nurbs_surface   data = { degU, degV, cp[][], w[][], knotsU, knotsV, thicknessMm }
     └─ op  "frame"     op = union,     inputs = [plate, arms]
         └─ op "vented" op = subtract,  inputs = [frame, vent_cutter]
```

Stored in `scene_nodes` and `params` (06). Changed only through commands (04 §3).

## 2. Who owns which code

The design file has two regions, so the agent and the user never overwrite each other.

```csharp
// ── AGENT REGION ── generated by the model; regenerated on design changes ──
public static class Design { public static void Build(Ctx ctx) { … } }
public static class Parts  { public static Voxels Arms(Ctx ctx) { … } … }

// ── USER REGION ── written by the emitter from user edits; the model must not edit ──
public static class UserEdits
{
    public static void Apply(Ctx ctx)
    {
        ctx.Op("vented", BoolOp.Subtract, "frame", "vent_cutter");
        ctx.Nurbs("canopy", NurbsSurfaces.Canopy(ctx));
    }
}
```

- The runner calls `Design.Build(ctx)` then `UserEdits.Apply(ctx)`.
- The analyzer rejects agent code that changes anything between the user-region markers (`BRIEF_USER_REGION`).
- When the agent renames or removes a part that a user edit refers to, the build fails with `DANGLING_REF` naming the edit; the UI offers to remap or drop it.

## 3. Parameters and equations

A parameter's `expr` is either a number or an expression over other parameters.

```
prop_d      = 5                                   [in]
n_arms      = 4
clearance   = 6                                   [mm]
arm_len     = (prop_d*25.4/2) / sin(pi/n_arms) + clearance       [mm]
arm_width   = 8.5                                 [mm]   governing
sigma_arm   = 6*F_arm*arm_len / (arm_width*arm_h^2)              [MPa]
```

- **Grammar** (`domain/expr.ts`): numbers, identifiers, `+ - * / ^`, parentheses, unary minus; functions `sin cos tan asin acos atan atan2 sqrt abs min max pow log exp floor ceil round clamp rad deg`; constants `pi`, `e`. Trig takes radians; `rad()` and `deg()` convert. A hand-written Pratt parser; JavaScript `eval` and `Function` are never used.
- **Evaluation:** topological order over the dependency graph; a cycle returns `PARAM_CYCLE` naming the loop; a value outside `min`/`max` returns `PARAM_RANGE`.
- **Where equations live:** in `params.expr` (source of truth), in the inspector (editable), and as comments in the generated code header. C# receives evaluated values through `ctx.P("name")`, so the engine never parses expressions.
- **Governing parameters** are checked against the built geometry by the validator (measured dimension within tolerance of the value).
- **Inspector UX:** each row shows name, expression, evaluated value in mono, unit. Typing `=` switches a value to an expression; dependents highlight while hovering; scrubbing a number by dragging its label is supported (`Shift` for fine).

## 4. Direct manipulation

### 4.1 Selection

Click selects a part (raycast against BVH-accelerated meshes); `Shift`-click adds; click on empty space clears. Hover shows a 1 px outline; selection shows a 2 px outline in `--ink` and opens the inspector. Selecting in the explorer and in the viewport stay in sync.

### 4.2 Transform gizmo

Built on three.js `TransformControls` (from r169 the controls are not an `Object3D`: add `controls.getHelper()` to the scene).

| Control | Behaviour |
|---|---|
| `W` / `E` / `R` | Move / rotate / scale |
| Arrows and rings | Coloured by axis (`--axis-x/y/z`); plane handles for two-axis moves |
| Snapping | 1 mm and 15° by default; hold `Shift` for 0.1 mm and 1°; `Ctrl` disables snapping |
| Space | `Q` toggles local / world |
| Numeric entry | While dragging, type a number and press Enter to set the exact offset; inspector fields edit the same values |
| Live feedback | The part's mesh moves on the client every frame; the readout shows Δx Δy Δz in mono beside the cursor |
| Commit | One `part.transform` command on release (07 §2) |
| Rebuild | If the part feeds a boolean, the op rebuilds in the background; until then its outline is dashed |

Non-uniform scale on a part forces a rebuild of that part at its stage resolution.

### 4.3 Tools in v1

| Tool | Command | Engine work |
|---|---|---|
| Move / rotate / scale | `part.transform` | Re-voxelise the transformed part mesh (cached) and re-run dependent ops |
| Boolean union / subtract / intersect | `op.add` | Booleans on cached part voxels |
| Mirror | `op.add mirror {plane}` | Mirror mesh, voxelise |
| Linear / polar pattern | `op.add pattern {count, step|axis}` | Kit pattern helpers |
| Offset / shell | `op.add offset|shell {mm}` | `Offset`, `Kit.Shell` |
| Fillet concave / round convex | `op.add fillet {mm, kind}` | `Kit.FilletClose`, `Kit.RoundOpen` |
| Hide / isolate / show all | `node.hide|show` | None |
| Duplicate | `node.duplicate` | Cache hit |
| Measure | read-only | BVH raycasts on the client; precise values from `engine.inspect` on demand |
| Section | view-only | Clipping plane + cap |

Boolean input order is the selection order (A − B for subtract). Op inputs collapse under the op in the explorer and stay editable.

## 5. NURBS

PicoGK is a voxel kernel, so NURBS here are *design surfaces* that become solids. They are exact while you edit them and exported as meshes (and as their own JSON definition), not as STEP B-rep.

**Math (implemented in `Kit.Nurbs`, mirrored in `app/src/viewport/nurbs.ts` for live handles):**

- Basis (Cox–de Boor): `N(i,0)(u) = 1 if u_i ≤ u < u_{i+1} else 0`; `N(i,p)(u) = (u − u_i)/(u_{i+p} − u_i) · N(i,p−1)(u) + (u_{i+p+1} − u)/(u_{i+p+1} − u_{i+1}) · N(i+1,p−1)(u)`, with 0/0 taken as 0.
- Curve: `C(u) = Σ N(i,p)(u)·w_i·P_i / Σ N(i,p)(u)·w_i`.
- Surface: `S(u,v) = ΣΣ N(i,p)(u)·N(j,q)(v)·w_ij·P_ij / ΣΣ N(i,p)(u)·N(j,q)(v)·w_ij`.
- Knots: clamped, `knots = n + p + 2` for `n + 1` control points; default uniform interior knots.

**To solid:** tessellate adaptively to a chordal tolerance (default `voxel/2`), then thicken by `thicknessMm`. Preferred path: PicoGK `Voxels.voxMeshShell` (added in 2.0). `VERIFY:` its exact signature with DumpApi; fallback is an offset shell mesh (both sides plus side strips) voxelised with `new Voxels(mesh)`. Curves become solids by sweeping a circle or a profile (`Kit.voxSweepCircle` along the tessellated curve).

**Editing:** select a NURBS node → its control net appears (points 8 px, net lines 1 px `--ink-3`); drag points with the same gizmo; weights and knot spacing in the inspector. The client re-tessellates the surface every frame for the preview; the engine rebuilds the solid on release.

**Storage:** control points, weights, knots, degrees and thickness in `scene_nodes.data_json`; the emitter writes them into the user region as literal arrays:

```csharp
public static class NurbsSurfaces {
  // S(u,v) = ΣΣ N_i,3(u) N_j,3(v) w_ij P_ij / ΣΣ N_i,3(u) N_j,3(v) w_ij   (degree 3×3, 5×4 control net)
  public static Kit.Nurbs.Surface Canopy(Ctx ctx) => new(
    degU: 3, degV: 3,
    cp: new Vector3[,] { { new(-40,-20,0), … } },
    w:  new float[,]   { { 1, 1, 1, 1 }, … },
    knotsU: Kit.Nurbs.ClampedUniform(5, 3), knotsV: Kit.Nurbs.ClampedUniform(4, 3),
    thicknessMm: ctx.P("canopy_t"));
}
```

## 6. The emitter and the code panel

`server/emitter/` turns user-owned nodes into C# deterministically (no model involved): same scene → byte-identical code. It also writes the file header:

```csharp
// PicoForge · project OneShotFly-Drone · variant v1.1-AeroOpt · rev 214 · 2026-11-24
// PARAMETERS
//   prop_d     = 5                         in
//   arm_len    = (prop_d*25.4/2)/sin(pi/n_arms)+clearance   = 95.8 mm
//   arm_width  = 8.5                       mm   governing
// Built with PicoGK 2.2.0 · Kit 1.4 · voxel 0.35 mm
```

**Code panel** (inspector → Code, or `Cmd/Ctrl + C` on a selected part):
- `Copy part`: the part's generator function plus the parameters it reads.
- `Copy file`: the full design file (both regions) with header.
- `Copy parameters`: JSON of name, expr, value, unit.
- `Diff`: compare with any earlier code version (`code_versions.parent_id` chain).

**Equivalence guarantee (tested):** compiling the copied file in a fresh project with the copied parameters produces the same geometry hash as the live scene (`CAD-EQUIV-*` in 11).
